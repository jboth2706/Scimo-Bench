# M7 — Pareto front

Size S · depends on: M4, M5, M6 · next: post-MVP

## Goal
Compare models on physics quality against inference cost; find the non-dominated set.

## Deliver
- `scimo_bench/plotter.py`: registered plot class `ParetoPlot(y, x, perf_condition,
  x_log, connect_sweeps, robust_dominance)` configured in `configs/plots.py` group
  `plots/pareto` (example `emd_vs_latency` in `docs/DESIGN.md`).
  - joins `kind=quality` rows (metric `y`, overall value) with `kind=perf` rows (metric `x`,
    restricted to `perf_condition`) over model + generation `condition`.
  - x may also be a static cost from `meta` / adapter `info()` (FLOPs per event, n_params)
    or training compute from the producer's run CSV (later).
  - dominance with `better` for y and lower-is-better for x; `robust_dominance` uses the
    intervals.
  - error bars from bootstrap (y) and repeats (x); `connect_sweeps` draws one line per model
    over its generation configs.
- `pareto.csv`: model, condition, x, y, intervals, `on_front`.

## Done when
- `emd_median` vs `latency_p50` for n6 AdamW vs Muon: plot + `pareto.csv`.
- Then with the depth-scaling models n5–n8 (both optimizers) once their predictions and perf
  runs exist.
- Unit test: synthetic points with a known front (including a dominated point and ties).
