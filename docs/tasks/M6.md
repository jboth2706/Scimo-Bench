# M6 — Performance path

Size M · depends on: M2 (a model to run), M4 (quality gate) · next: M7

## Goal
Measure inference cost of the same models, honestly and comparably, and write it into the
same report.

## Deliver
- `scimo_bench/perf.py`:
  - adapter protocol (`load`, `make_batch`, `predict`, `info`; `docs/DESIGN.md`), loaded from
    `model.perf.adapter = "pkg.module:Class"`; missing adapter → `missing`.
  - scenarios `offline` (events/s per batch size; GPU-s per 1,000 events; peak memory via
    `torch.cuda.max_memory_allocated`) and `single` (latency p50/p90/p99 at batch size 1).
  - timing: warmup batches excluded and reported (`warmup_s`), compile time reported
    (`compile_s`), `torch.cuda.synchronize()` around timed regions, `repeats` with interval;
    model time (inputs on device) and end-to-end time (incl. reading + detokenizing) as
    separate metrics.
  - hardware fingerprint (GPU name, count, driver, torch, CUDA, precision, compiled) into
    `meta` and the `condition` column.
  - `quality_gate` from the task: perf rows get `invalid` if the model's quality report for
    the same generation config fails the gate (needs a quality run first; else `missing`).
  - rows with `kind=perf` appended to `report.csv` (same columns).
- Perf configs in `configs/perf.py`: `single_a100`, `offline_a100` (batch sizes 1, 64, 256;
  warmup 20; repeats 5; 20,000 events; bf16).
- In hep4m_scimo: `src/hep4m_scimo/bench/adapters.py: TokenStreamAdapter` (reuses M2's
  model loading and `decode_chunk`; `info()` reports n_params, family, generation,
  FLOPs per event ≈ 2 · N_params · tokens per event).
- pixi feature/env `perf` (pytorch, hep4m_scimo editable from `../scimo`).
- An sbatch script to run `stage=perf` on 1× A100.

## Done when
- GPU job measures both n6 models in both scenarios; repeat scatter < 5 %.
- Compile and warmup appear as their own rows, not mixed into throughput or latency.
- A synthetic failing gate turns perf rows into `invalid`.

## Notes
- Never on the login node. GPU queue is slow; test the code path with a tiny model on CPU
  (`device=cpu`) in unit tests, GPU only for the real measurement.
